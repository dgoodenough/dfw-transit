# network/ — the source of truth

Six plain CSV tables describe the whole plan. Edit them by hand, then run
`python -m dfwt validate` and `python -m dfwt build`. Nothing here is
generated by the build, so hand edits are never overwritten.

| Table | One row per | Columns |
|---|---|---|
| `lines.csv` | line | `line_id`, `name` (unique), `mode` (`metro` / `brt` / `commuter`), `status` (`existing` / `proposed`), `color`, `headway_min` (blank = mode default in `config.json`), `notes` |
| `stations.csv` | physical stop | `station_id`, `name`, `lat`, `lon` |
| `line_stops.csv` | line × stop | `line_id`, `seq`, `station_id`, `year_opens` (the year *this line* starts serving *this stop*) |
| `line_segments.csv` | line × gap between consecutive stops | `line_id`, `seq` (stop `seq` → `seq+1`), `year_opens` (track open for this line), `grade` (`surface` / `elevated` / `tunnel`, drives cost), `geometry_wkt` |
| `service.csv` | frequency change | `line_id`, `from_year`, `headway_min`, `note` |
| `transfers.csv` | walk link | `station_a`, `station_b`, `walk_min` (blank = from distance), `note`; stops within 400 m are linked automatically |

Rules the model applies:

- A line runs on a segment once the segment's year has come. A stop is served
  once its own year has come **and** track reaches it. Stops that open later
  than the track around them are infill stations; trains run through until then.
- Station opening year, serving lines, colors, activity and costs are all
  derived. They are not stored.
- Track shared by several lines (the same station pair, same mode) is costed
  once, to the line that opens it first. A station is costed once.

`CHANGELOG.md` records every change from v1 to v2.
